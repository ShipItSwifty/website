ShipIt `0.4.0` adds the `firebase-app-distribution` workflow action. It uploads a signed iOS IPA or Android APK/AAB to Firebase App Distribution, attaches release notes, and distributes the build to Firebase tester groups or individual testers.

## What you need

- A Firebase project with an iOS or Android app registered for App Distribution
- The Firebase app ID, found under **Project settings -> Your apps -> App ID**
- At least one Firebase tester group alias or tester email address
- A Google service account with access to the Firebase project
- A signed artifact produced earlier in the workflow

Create the service account in Google Cloud IAM for the same Firebase project and grant it the Firebase App Distribution Admin role. On GitHub Actions, prefer keyless Workload Identity Federation over a JSON key. Elsewhere, create a JSON key and store it in your CI secret manager, not in the repository.

## Configure credentials

Choose one credential source. ShipIt checks them in this order:

1. A Workload Identity Federation pair: `workload_identity_provider` with `service_account_email` on the action, or `GOOGLE_WORKLOAD_IDENTITY_PROVIDER` with `GOOGLE_SERVICE_ACCOUNT_EMAIL`
2. `service_account_path` on the workflow action
3. `FIREBASE_SERVICE_ACCOUNT_JSON`, containing the raw JSON key
4. `GOOGLE_APPLICATION_CREDENTIALS`, containing the local path to the JSON key

### Keyless on GitHub Actions

With Workload Identity Federation there is no key to store or rotate. GitHub mints a short-lived OIDC token for the job, and Google exchanges it for access as the service account. Grant the repository's identity `roles/iam.workloadIdentityUser` on the service account, then let the job request a token:

```yaml
permissions:
  contents: read
  id-token: write
```

```yaml
- action: firebase-app-distribution
  options:
    app_id: ${FIREBASE_IOS_QA_APP_ID}
    artifact_path: ./build/export/MyApp.ipa
    groups: [qa-testers]
    workload_identity_provider: projects/123456789/locations/global/workloadIdentityPools/github/providers/my-repo
    service_account_email: firebase-distribution@my-project.iam.gserviceaccount.com
```

Both keys must be set together; one without the other is rejected.

### With a JSON key

For other CI providers, pass the raw JSON from a secret:

```bash
export FIREBASE_SERVICE_ACCOUNT_JSON="${FIREBASE_SERVICE_ACCOUNT_JSON}"
export FIREBASE_IOS_QA_APP_ID="1:1234567890:ios:abc123"
```

Do not inline the JSON key in `Shipfile.yml`.

## iOS workflow

Export an ad-hoc IPA, then send it to a Firebase tester group:

```yaml
app:
  scheme: MyApp

archive:
  export_method: ad-hoc

workflows:
  beta:
    - action: archive
    - action: export
      options:
        output_directory: ./build/firebase
    - action: firebase-app-distribution
      options:
        app_id: ${FIREBASE_IOS_QA_APP_ID}
        artifact_path: ./build/firebase/MyApp.ipa
        groups: [qa-testers]
        release_notes: "Build {{build_number}}"
```

## Android workflow

Build an APK for direct tester installation, then distribute it:

```yaml
platform: android

android:
  module: app
  build_variant: release

workflows:
  beta:
    - action: build
    - action: firebase-app-distribution
      options:
        app_id: ${FIREBASE_ANDROID_QA_APP_ID}
        artifact_path: ./app/build/outputs/apk/release/app-release.apk
        groups: [qa-testers]
        release_notes: "Build {{build_number}}"
```

Firebase app IDs encode their platform. ShipIt validates that an iOS app ID receives an IPA, and an Android app ID receives an APK or AAB, before uploading.

## Verify safely

Run the workflow-level dry run first:

```bash
shipit run beta --dry-run --output json
```

For a Firebase-only preview, set `dry_run: true` on the action. This validates the app ID, artifact path, and audience without uploading.

```yaml
- action: firebase-app-distribution
  options:
    app_id: ${FIREBASE_ANDROID_QA_APP_ID}
    artifact_path: ./app/build/outputs/apk/release/app-release.apk
    groups: [qa-testers]
    dry_run: true
```

When a distribution succeeds, structured output includes Firebase's tester installation URL and console URL when they are available. Tester email addresses are not included in the output.
